# Orb Agent Policies

This repository contains the policy files for the [Orb agent](https://orb.community/) running in the workshop environment. The agent polls this repo roughly every 60 seconds, detects changes, and applies them automatically — no restart required.

## How it works

```text
Gitea (this repo)
      │
      │  polls every ~60s
      ▼
  Orb Agent
      │
      ├──► Diode ──► NetBox branch   (discovery policies)
      │
      └──► Prometheus remote write   (monitoring policies)
```

The **selector.yaml** file is the master switch: it maps policy names to their YAML files and controls which ones are enabled. To activate a policy, add (or enable) an entry in the selector and commit.

## Files (stock state)

The repo ships with only the minimum needed for Module 1's web monitoring:

### `selector.yaml`
Master control file. Maps policy names to YAML files and enables/disables each. Stock content:

```yaml
web_monitor:
  selector:
    agent_name: orb-agent
  policies:
    web_monitor:
      path: web_monitor.yaml
      enabled: true
```

Module 2 has participants append an `srlinux_discovery` block to wire in the SR Linux discovery policy.

### `web_monitor.yaml`
Runs continuous HTTP availability checks against the web server (`http://192.168.2.2`) and exports the results as Prometheus metrics via remote write.

Metrics produced:

- `httpcheck_status` — `1` if the server returns a 2xx response, `0` otherwise
- `httpcheck_duration_milliseconds` — round-trip response time

Enabled from the start of the workshop. These metrics power the Grafana dashboard.

## Files (added during the workshop)

### `srl_devices.yaml` *(generated by NetBox in Module 2)*
Discovers SR Linux devices via gNMI and ingests them into NetBox via Diode.

**This file does not ship with the repo.** It's rendered from NetBox by the **Run Orb Discovery** custom script (Customization → Scripts) in Module 2, Step 10. The script queries NetBox for active Nokia Routers with a primary IPv4 in the chosen site, templates the policy, and commits it here via the Gitea API. The file's header carries a `DO NOT EDIT BY HAND` marker — to change it, re-run the script.

What gets ingested by the resulting discovery run:

- Device inventory (platform, serial, OS version)
- Interfaces and their operational state
- IP addresses

## Workshop progression

| Module | Action |
|--------|--------|
| Module 1 | `web_monitor` is already enabled — HTTP metrics flow to Prometheus/Grafana |
| Module 2 | (optional Step 10) Run the **Run Orb Discovery** script in NetBox to render `srl_devices.yaml`; append an `srlinux_discovery` block to `selector.yaml`; watch the NetBox verification branch populate |
| Module 6 | Re-run the same NetBox script to regenerate `srl_devices.yaml` from current source-of-truth state, triggering a fresh discovery run into a branch |
